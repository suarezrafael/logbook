# V91 meta-complexity reduction ledger

This ledger prevents transfers by analogy. Every row must specify the exact
problem variant, reduction type, oracle use, promise, distribution, and
parameter loss.

## 1. Variant dictionary

### Range avoidance

```text
Input:  circuit C:{0,1}^n -> {0,1}^m, m>n
Output: y not in Range(C)
```

Record the circuit class, stretch `m-n`, allowed oracle, deterministic versus
randomized search, and whether a remote-point distance is required.

### Remote point

```text
Input:  circuit or code-like map C
Output: y whose Hamming distance from Range(C) exceeds r
```

An avoided point is the radius-zero case. A remote point is stronger only when
the external reduction consumes the distance guarantee.

### MCSP / GapMCSP

Record:

- truth-table length;
- circuit basis and size threshold;
- exact versus gap promise;
- approximation factor;
- reduction type and randomness.

### Time-bounded Kolmogorov variants

Do not merge these names:

- `K^t`: shortest description producing a string within time `t`;
- `Kt`: Levin-style description length plus logarithmic running time;
- `MKTP`, `MINKT`, and promise/gap versions;
- randomized or probabilistic variants;
- conditional variants.

Their completeness, hardness, and one-way-function consequences differ.

## 3. Known laboratory starting points

### V85 support-width remote point

For support-connectivity branchwidth `k=O(sqrt(log m))`, V85 constructs a point
at distance

```text
r = Omega((m-n)/log m)
```

from the range of an explicit locality-three circuit.

This is an algorithmic theorem on a narrow structural class. It is not yet a
meta-complexity theorem.

### V85 `Eval_H`

The missing output of `Eval_H` is a universal support-only candidate list. This
is a structured range-avoidance formulation. Any transfer to MCSP, `K^t`, `Kt`,
rigidity, proof complexity, or one-way functions must identify a published
reduction whose source class and parameters match `Eval_H`.

## 5. First audit — V85 remote point to rigidity

The locality-three range-avoidance literature already contains reductions from
explicit rigid-matrix construction to `NC0_3-Avoid` at specific stretch and
oracle parameters. V91 must compare directions carefully:

```text
known form:
algorithm for an Avoid instance class
  -> explicit rigid object
```

The V85 theorem applies only under low support branchwidth. The required
question is not whether remote points resemble rigid objects. It is:

```text
Do the Avoid circuits produced by the published rigidity reduction have
support branchwidth O(sqrt(log m)), or can their structure be transformed into
that regime without destroying the reduction?
```

If no such guarantee exists, the V85 algorithm does not activate the rigidity
consequence.

### Go condition

Prove a width bound for every circuit generated by the external reduction, with
all stretch and oracle parameters preserved.

### No-go condition

Show that the generated circuits can contain linear-width support structures,
or that any width-reducing transformation loses the required stretch or
explicitness.

## 6. Second audit — remote points to MCSP or Kolmogorov complexity

A point outside a range has high complexity only relative to the generator
whose range is avoided. To obtain MCSP or Kolmogorov complexity, the reduction
must ensure that every low-complexity string lies in the range of the supplied
map.

Required covering statement:

```text
{strings with target complexity <= s}
  subseteq Range(G_s)
```

with `G_s` belonging to the circuit class solved by the laboratory and with
parameters small enough for the algorithm.

Without this inclusion, a remote point may still have a short circuit or short
program unrelated to `G_s`.

### Candidate construction audit

For each complexity measure, compute:

1. seed length required to enumerate all descriptions/programs/circuits of
   complexity at most `s`;
2. output length;
3. locality and depth of the universal evaluator;
4. support branchwidth of that evaluator;
5. distance interpretation, if any;
6. runtime of V75/V77 on the evaluator.

The likely bottleneck is that a universal evaluator need not be locality three
or low support width.

## 7. Third audit — worst-case to average-case consequences

Hirahara's results and later refinements are variant-sensitive. V91 must not
write `MCSP has a worst-case-to-average-case reduction` without specifying:

- exact or gap problem;
- approximation factor or additive error;
- randomized, zero-error, or heuristic algorithm;
- derandomization assumption;
- distribution over instances;
- black-box or non-black-box nature.

The laboratory contributes only if it supplies a source problem or reduction
that matches one of these exact statements.

## 8. Fourth audit — one-way functions and Kolmogorov complexity

The Liu--Pass equivalences concern specific forms of mild average-case hardness
for time-bounded Kolmogorov complexity, with later work treating worst-case,
boundary, randomized, or promise variants under different assumptions.

A valid chain must look like:

```text
laboratory theorem
  -> exact average-case or worst-case hardness statement for variant X
  -> cited Liu--Pass theorem for the same X and assumptions
  -> existence of one-way functions.
```

A deterministic algorithm for a narrow structured range-avoidance class does
not point in this hardness direction without an additional reduction.

## 9. V91 deliverable decision

### Go

Continue the meta-complexity front if one row gives a parameter-preserving new
reduction, a simplification of a known reduction, or a new activation of an
existing consequence for a structural circuit class.

### No-go

If the universal evaluator has excessive locality or width, or the known
rigidity circuits do not fall into the V85 tractable regime, record the exact
parameter obstruction and stop translating by analogy.

## 10. Nonclaims

Range avoidance, remote points, MCSP, `K^t`, `Kt`, and one-way functions are not
interchangeable names for high complexity. A missing output is not automatically
an MCSP-hard truth table. A remote point is not automatically Kolmogorov random.
An arXiv adjacency or shared terminology is not a reduction.
