# Laboratory V95 — balanced-definition canonicalization and PP-hard next bit

## Classification

V95 is a **barrier-and-closure laboratory**. It resolves the exact gap left by
V94: arbitrary-prefix hardness can be made genuinely canonical.

The key device is not a forcing gadget with a biased accepting set. It is a
balanced definition gate

```text
BALDEF_f(z,a,b) = z XOR f(a,b).
```

When `z` is fresh, toggling `z` pairs the zero and one children exactly. The V92
tie-zero rule therefore chooses output `0`, and conditioning on that canonical
bit uniquely installs the equation `z=f(a,b)`.

This gives a composable way to load an arbitrary fan-in-two computation into a
canonical all-zero prefix.

## Main theorem

There is a fixed seven-type Boolean gate language of maximum arity three such
that the following task is PP-hard at exact minimal stretch `M=N+1`:

```text
given C, compute a specified next bit of the V92 canonical halving word.
```

The hard instances are stronger than an arbitrary-prefix promise: every prior
bit is **provably generated by the canonical rule itself**, and every one of
those prior steps is an exact tie.

For a pair of 3-CNFs `F0,F1`, V95 first loads their truth values `t0,t1` through
balanced definition gates. The canonical prefix is `0^q`. The next ternary gate
is

```text
H(s,t0,t1) = NOT t0   if s=0,
             t1       if s=1.
```

Writing `A=#sat(F0)` and `B=#sat(F1)`, after the canonical loader prefix,

```text
N(0^q 0) = A + (2^n-B),
N(0^q 1) = (2^n-A) + B.
```

Hence the next canonical bit is zero exactly when `A<=B`. V94 already established
that this comparison source is PP-complete.

## Consequence for the V92 route

An algorithm that computes the **exact V92 canonical halving output** for every
`NC0_3` stretch-one circuit can reveal this PP-hard bit. Therefore a polynomial-
time exact implementation of that particular canonical policy would imply
`P=PP` (and consequently `P=NP`).

This is a closure result for the exact canonical-halving strategy, **not** for
range avoidance itself. A different algorithm may find some other absent word
without reproducing the canonical word or any exact count comparison.

## Fixed language

The compiler needs only:

```text
4 signed-OR balanced-definition tables,
1 AND balanced-definition table,
1 ternary selector/comparison table H,
1 projection table for output padding.
```

Maximum locality is three throughout.

## Deterministic executable audit

The primary and independent implementations exhaust all ordered pairs of the
64 signed three-literal clauses over two source variables:

```text
4,096 compiled source pairs,
16,384 canonical balanced-definition decisions,
0 nonzero loader-prefix bits,
0 loader balance failures,
0 final child-count formula mismatches,
0 PP-comparison/next-bit mismatches,
0 full canonical outputs found in the range.
```

The finite audit is regression evidence only. The canonicalization lemma and
hardness reduction are symbolic and are stated in `THEOREMS.md`.

## Scientific consequence

V94 said: exact comparison for arbitrary prefixes is too strong.

V95 now says something sharper: **even the exact canonical trajectory chosen by
V92 contains PP-hard information**. Therefore the next useful laboratory should
not attempt to speed up the same exact canonical word. It must exploit a weaker
certificate or construct a different avoided output.

## Nonclaims

V95 does not prove that finding *any* avoided output is PP-hard, does not prove
that every range-avoidance algorithm computes the canonical word, does not
improve the Huang-Li-Zhong `O(n*2^(n/2))` `NC0_3-Avoid[n,n+1]` runtime, does not
establish a new circuit lower bound, does not claim novelty or peer review, and
does not resolve P versus NP.
