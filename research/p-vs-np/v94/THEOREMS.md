# Laboratory V94 — child-count comparison as a fixed-language counting problem

## 1. The comparison primitive

For an explicit Boolean circuit

```text
C=(C_0,...,C_{M-1}):{0,1}^N -> {0,1}^M
```

and a prefix `p in {0,1}^j`, define

```text
N_C(p)   = |{x : C_0(x)...C_{j-1}(x)=p}|,
N_C(pb)  = |{x : C_0(x)...C_{j-1}(x)=p and C_j(x)=b}|.
```

The V92 canonical policy chooses the next bit

```text
b*=0 iff N_C(p0) <= N_C(p1),
```

and chooses `1` otherwise. V94 studies the decision problem behind this sign.

For a fixed finite gate language `Gamma` of fan-in at most three, let
`AP-CHILD-COMP(Gamma)` be the following promise-free decision problem:

```text
input:  an NC0_3 circuit C using Gamma with M=N+1,
        and an arbitrary prefix p of length j<M;
question: is N_C(p0) <= N_C(p1)?
```

The prefix is part of the input. It is not promised to have been generated by
the V92 canonical policy.

## 2. A fixed nine-gate language

Let `a,b,z,s,u` be Boolean variables and let `alpha,beta,c` range over
`{0,1}`. Define the following relations/functions.

### Definition gates

For each `alpha,beta`,

```text
DEF_{alpha,beta}(z,a,b)
  = 1  iff  z = ((a xor alpha) OR (b xor beta)).
```

There are four such ternary truth tables.

### Conditional-clause gates

For each active selector value `c` and literal sign `alpha`,

```text
COND_{c,alpha}(s,u,z)
  = 1 iff (s != c) OR (u xor alpha) OR z.
```

There are four such ternary truth tables. When `s!=c` the relation is
identically one; when `s=c` it enforces the two-literal disjunction
`(u xor alpha) OR z`.

### Projection

```text
PROJ(s)=s.
```

This is a unary gate, so the fixed language has maximum arity three. If a
strict arity-three presentation is desired, `PROJ(s,a,b)=s` is the same local
function with two inessential arguments.

Thus

```text
Gamma_V94 = {4 DEF tables, 4 COND tables, PROJ}
```

contains nine fixed gate types.

## 3. Source comparison problem

Define

```text
COMPARE-#3SAT_<=
  = {(F0,F1) : #sat(F0) <= #sat(F1)},
```

where the two formulas use a common declared variable set and clauses have
width at most three.

### Lemma 3.1 — `COMPARE-#3SAT_<=` is PP-complete

Membership follows because the difference of two `#P` functions is a `GapP`
function, and a non-strict comparison can be written as a strict positivity
question after adding one.

For hardness, let `L` be any language in `PP`. By the GapP characterization of
PP there exist `#P` functions `a,b` such that

```text
x in L  iff  a(x) > b(x).
```

The two functions

```text
A(x)=2*b(x)+1,
B(x)=2*a(x)
```

are again `#P` functions and satisfy

```text
A(x) <= B(x)  iff  a(x) > b(x).
```

A standard Cook-Levin tableau construction can be made parsimonious by keeping
one accepting tableau for each nondeterministic accepting path. A Tseitin
conversion using equivalence constraints gives a unique extension for every
satisfying assignment and therefore preserves the count exactly while reducing
to width at most three. Forced padding variables can equalize the two declared
variable sets without changing either count. Applying this construction to
`A` and `B` yields the required pair `(F0,F1)`.

This lemma is a standard counting-complexity consequence; V94's new laboratory
object is the bounded-locality stretch-one compiler in the next section, not a
novelty claim for the source problem.

## 4. Exact stretch-one compiler

Let `F0,F1` be 3-CNF formulas over the same `n` original variables. Let the
total number of clauses across both formulas be `r`.

Introduce:

```text
one selector s,
one auxiliary z_C for every clause C,
D=max(0, r-n-1) free dummy input variables.
```

The total number of circuit inputs is

```text
N = n + 1 + r + D.
```

For every clause

```text
C=(l1 OR l2 OR l3)
```

of formula `F_c`, add two output gates, in this order:

```text
DEF:   z_C = (l2 OR l3),
COND:  (s != c) OR l1 OR z_C.
```

Literal signs select one of the fixed `DEF`/`COND` truth tables from
`Gamma_V94`. Fix every one of these `2r` output gates to `1` in the prefix

```text
p = 1^(2r).
```

The next output gate is `PROJ(s)`. Pad the remaining output positions with
projections until the total output count is

```text
M=N+1.
```

This is possible because

```text
2r <= N
```

by the definition of `D`.

### Lemma 4.1 — unique auxiliary extension

For every assignment to the original variables and selector, the `DEF` prefix
gates determine every `z_C` uniquely.

**Proof.** Each equation is exactly

```text
z_C = l2 OR l3.
```

The auxiliaries occur on the left of distinct equations. QED.

### Lemma 4.2 — branch semantics

Conditioned on `s=c`, every conditional gate belonging to `F_{1-c}` is a
tautology, while each conditional gate belonging to `F_c` enforces its source
clause exactly after substitution of the uniquely determined auxiliary.

**Proof.** Off the active selector branch, `(s != c)` is true. On the active
branch the gate reduces to `l1 OR z_C`; by Lemma 4.1 this is
`l1 OR l2 OR l3`. QED.

### Theorem 4.3 — exact scaled child counts

For the compiled circuit,

```text
N_C(p0) = 2^D * #sat(F0),
N_C(p1) = 2^D * #sat(F1).
```

**Proof.** Fix `s=c`. By Lemmas 4.1 and 4.2, each satisfying assignment of
`F_c` has exactly one extension to all `z_C` variables satisfying the prefix,
and a nonsatisfying original assignment has none. The `D` dummy inputs are
unconstrained and contribute exactly a factor `2^D`. QED.

### Corollary 4.4 — comparison is preserved

```text
#sat(F0) <= #sat(F1)
iff
N_C(p0) <= N_C(p1).
```

The reduction is polynomial-time, uses a fixed gate language of maximum arity
three, and has exact minimal stretch `M=N+1`.

## 5. PP-completeness theorem for arbitrary prefixes

### Theorem 5.1

`AP-CHILD-COMP(Gamma_V94)` is PP-complete under polynomial-time many-one
reductions, even restricted to stretch-one circuits `M=N+1`.

**Membership.** For fixed `(C,p,b)`, a nondeterministic polynomial-time machine
can guess `x in {0,1}^N`, evaluate the constant-locality gates, and accept
exactly when the prefix plus child bit is satisfied. Hence each child count is
a `#P` function. The predicate

```text
N_C(p0) <= N_C(p1)
```

is a sign test of the GapP function

```text
N_C(p1)-N_C(p0)+1,
```

and is therefore in `PP`.

**Hardness.** Compose Lemma 3.1 with Theorem 4.3. QED.

### Interpretation

This is a barrier for algorithms that demand an exact comparator for *every
arbitrary prefix*. Unless `P=PP`, there is no polynomial-time exact comparator
for this fixed language on all such prefixes.

It is not a hardness theorem for the V92 canonical sequence and is not a
hardness theorem for range avoidance itself.

## 6. Mandatory canonical-prefix separation

The reduction above intentionally does not smuggle arbitrary-prefix hardness
into the canonical sequence.

Every `DEF` truth table has exactly four ones and four zeros on its eight local
assignments. Order a `DEF` gate first. All other circuit inputs are free, so at
the empty prefix its two child counts are equal. The V92 tie rule therefore
chooses

```text
canonical first bit = 0.
```

The hardness reduction instead fixes every `DEF` gate to

```text
hardness-prefix bit = 1.
```

### Proposition 6.1

For the explicit compiler and gate ordering above, the hardness prefix is not
the V92 canonical prefix already at its first bit.

This proposition does **not** prove that canonical-prefix comparison is easy,
or that no different PP-hardness compiler can follow canonical prefixes. It
only prevents Theorem 5.1 from being misreported as such a result.

## 7. Polynomial affine branch

Suppose every output gate is affine:

```text
C_i(x)=c_i xor <a_i,x>
```

over `GF(2)`, with `|supp(a_i)|<=3` if desired.

Fixing a prefix bit `p_i` is exactly the linear equation

```text
<a_i,x> = p_i xor c_i.
```

Thus every prefix fiber is an affine linear system.

### Theorem 7.1 — exact affine child comparison is in P

For every affine circuit and every prefix, `N_C(p0)` and `N_C(p1)` can be
computed in polynomial time by Gaussian elimination. Each count is either zero
or

```text
2^(N-rank).
```

Therefore their comparison is polynomial-time.

### Theorem 7.2 — incremental canonical affine comparator

Maintain a row-echelon basis for the current consistent prefix system.
For the next affine output row:

1. if its coefficient vector is independent of the current rows, both child
   fibers have equal size, so the V92 tie rule chooses `0` and the zero-output
   equation is inserted into the basis;
2. if the row is dependent, exactly one output bit is forced on the current
   nonempty fiber, so the other child is empty and the canonical rule chooses
   that empty child;
3. after the prefix becomes empty, both child counts remain zero and every
   remaining canonical bit is `0`.

This is a deterministic polynomial-time canonical-bit evaluator using one
maintained `GF(2)` basis.

### Corollary 7.3 — affine stretch-one avoidance is polynomial-time

For `M=N+1`, the canonical halving output of an affine circuit is outside the
range. Equivalently, before or at output `N`, linear dependence forces an empty
child; alternatively the generic halving invariant reduces a starting fiber of
size `2^N` through `N+1` choices to zero.

This is the expected affine tractable control and is consistent with the
classical Boolean counting-CSP affine dichotomy. No novelty is claimed.

## 8. Executable audits

The deterministic implementation checks:

```text
64 signed three-literal clauses over two variables,
4,096 ordered single-clause source pairs,
0 exact child-count mismatches,
0 stretch-one mismatches,

16 affine Boolean functions on three variables,
65,536 four-output affine circuits,
262,144 exact child decisions,
0 Gaussian-vs-brute-force child-count mismatches,
0 incremental-vs-exact canonical-output mismatches,
0 canonical affine outputs found in the range.
```

The finite audit validates the implementation. Theorems 4.3, 5.1, 7.1, and 7.2
are symbolic and do not depend on the census.

## 9. Scope and nonclaims

V94 proves a PP-completeness barrier only for arbitrary-prefix exact child
comparison over the explicit fixed language `Gamma_V94`. It does not prove
PP-hardness of V92-generated canonical prefixes, does not show that construction
of an avoided word requires exact comparison, does not improve the
`O(n*2^(n/2))` `NC0_3-Avoid[n,n+1]` baseline of Huang-Li-Zhong, does not prove a
new circuit lower bound, does not establish novelty or peer review, and does not
resolve P versus NP.
